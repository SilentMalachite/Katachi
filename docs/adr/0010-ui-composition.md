# ADR-0010: UI の構成と、§7 の非機能要件を機械で担保する方法

- 状態: 承認
- 日付: 2026-08-09

---

## 背景

`docs/spec-core.md` §7 は UI の非機能要件を 7 項目挙げ、
「**好みではなく、視覚・前庭系の負荷を避けるための合理的要件**」「実装時に落とさない」と明記している。
しかし §1 が定めるのは `MainWindow` / `JobTableModel` / `SettingsPanel` という**ファイルの顔ぶれだけ**で、
配置も、7 項目をどう守るかも決まっていない。

守り方を決めないと、この 7 項目は「気をつける」で終わる。
Phase 0〜1 で示したとおり、**このプロジェクトは人手の注意ではなく機械検査で不変条件を守ってきた**
（不変条件スキャナ、否定側 `static_assert`、フィクスチャの自己検証）。§7 も同じ扱いにする。

さらに、§7 の 1 項目が実装上の矛盾を含んでいた。

> モーダルダイアログは「破壊的操作の確認」のみ。エラーはステータス行と結果列に表示

**字義どおりだと、出力先フォルダの選択に `QFileDialog` を使えない。**
`QFileDialog` はモーダルであり、破壊的操作の確認ではない。
`CLAUDE.md` 停止条件 2（指示書内の矛盾）に該当するため、実装前に停止して判断を仰いだ。

## 選択肢

### 配置

- **A. 単一ウィンドウの縦 3 段**（ジョブ表 / 設定 / 実行と進捗）
- B. 左右 2 分割（左に表、右に設定）
- C. タブ切り替え

### モーダルの扱い

- **A. 用途を列挙して限定する**（出力先の選択と、上書き実行の確認のみ）
- B. `QFileDialog` を使わず、出力先はパス入力欄とフォルダの D&D のみで受ける

## 決定

### 配置は縦 3 段（単一ウィンドウ）

```
+--------------------------------------------------+
| ジョブ一覧 (QTableView)                           |  <- 入力 / 出力 / 状態 / 理由
|   D&D の受け口。ファイル・フォルダを落とせる        |
+--------------------------------------------------+
| 設定 (SettingsPanel / QFormLayout)                |  <- 形式・品質・リサイズ・アルファ
|                                                  |     メタデータ・ICC・命名・出力先・衝突
+--------------------------------------------------+
| [開始] [キャンセル]  進捗バー   ステータス行        |
+--------------------------------------------------+
```

`QDockWidget` を使わない（フローティングパネル禁止）。ウィンドウは 1 枚のみ。

### モーダルは 2 つの用途に限定する

**`QFileDialog` を出力先フォルダの選択に使う。**
§7 の趣旨は「エラーや通知でユーザの動線を止めるな」であり、
ユーザが自ら起動する OS 標準のファイル選択はこれに当たらないと判断した（利用者の判断を得た）。

**モーダルを出してよいのは次の 2 つだけ。**

1. 出力先フォルダの選択（`QFileDialog::getExistingDirectory`）
2. `CollisionPolicy::Overwrite` を選んだ状態で実行を開始するときの確認（ADR-0009）

**それ以外では出さない。** エラーはステータス行と結果一覧の「理由」列に表示する。

### 7 項目の担保方法

| # | 要件 | 担保 | 検査 |
|---|---|---|---|
| 1 | アニメーション・フェード・スライドを使わない | `QPropertyAnimation` / `QGraphicsEffect` / `QTimeLine` を使わない | `src/` の `grep` が 0 件であることをテストで確認 |
| 2 | 進捗は 200ms 以下の間隔で更新しない | ワーカーは `std::atomic<int>` を増やすだけ。main thread の `QTimer(200ms)` が読んで emit する | `interval() == 200`。1000 件のバッチで進捗シグナルが 100 回未満 |
| 3 | ダークモードはシステム設定に追随 | `setStyleSheet` / `setPalette` を書かない。Qt の既定に任せる | `src/` の `grep` が 0 件 |
| 4 | 全機能がキーボードのみで操作可能。タブ順を明示 | `setTabOrder()` で主要ウィジェットを明示的に連結。ボタンにニーモニック | タブ順の連結をテストで確認 + 実機確認 |
| 5 | 自動スクロール禁止 | `QTableView::setAutoScroll(false)`。`scrollTo` / `scrollToBottom` を呼ばない | 行追加後にスクロール位置が変わらない |
| 6 | モーダルは破壊的操作の確認のみ | 上記 2 用途に限定 | 失敗発生時に `QApplication::activeModalWidget() == nullptr` |
| 7 | ウィンドウは単一 | `QMainWindow` 1 枚。`QDockWidget` を使わない | `src/` の `grep` が 0 件 |

## 帰結

- **`grep` による検査 3 件（#1 / #3 / #7）はテストとして `ctest` に載せる。**
  人手のレビューに頼らない。不変条件スキャナと同じ考え方だが、
  **スキャナ本体（`scan_invariants.cmake`）には足さない。**
  §7 は UI の要件であり、`CLAUDE.md` の「絶対禁止」を機械化した 6 種（+ INV7）とは
  由来が異なる。混ぜると、どちらの根拠で落ちているのか分からなくなる。
- **進捗の間引きを main thread のタイマで行うことにより、ワーカーはシグナルを一切出さない。**
  1000 件でシグナルが 1000 回飛ぶ設計を最初から採らない。
- **キャンセルは二段構えにする。** `QFuture::cancel()` は待機中の項目を止めるが、
  Qt 6.8 の公式ドキュメントには**実行中の項目を中断するとは書かれていない**
  （`qfuture.html#cancel`「キャンセルは非同期」）。
  そのため `JobRunner::runOne()` は**着手直前に `ProgressSink::isCancelled()` を見て早期終了する**。
  実行中の 1 件は終わるまで待つが、残りは着手しない。
  **書かれていない挙動を期待しない。**
- **表示用の文言はすべて `src/app` に置く。** core / io には置かない。
  INV3A / INV3B が禁じるのはフォーマット名の文字列リテラルだけであり
  （`docs/progress/phase1.md` の T6 の項）、UI 文言の置き場所は機械検査されない。
  設計方針として守る。
- 出力形式の選択肢は `CapabilityTable::encodable()` から作る。
  **`SettingsPanel` にフォーマット名を書かない**（INV3B が検出する）。
