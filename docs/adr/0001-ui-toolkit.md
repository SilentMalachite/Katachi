# ADR-0001: UI ツールキットに Qt Widgets を採用する

- 状態: 承認
- 日付: 2026-08-09

---

## 背景

Katachi は画像フォーマット変換のデスクトップアプリで、UI の形状は
「ファイル一覧（表）＋ 設定パネル ＋ 進捗・結果表示」に固定されている（`docs/spec-core.md` §7）。

UI 非機能要件として、アニメーション・フェード・スライドを一切使わないこと、
自動スクロールを行わないこと、ダークモードはシステム設定に追随することが定められている。
これらは好みではなく、視覚・前庭系の負荷を避けるための要件である。

Qt 6 で UI を作る手段は Qt Widgets と Qt Quick / QML の 2 つがある。

## 選択肢

### A. Qt Widgets

ネイティブウィジェットベース。`QTableView` / `QFormLayout` など、表と設定フォームの
既製部品が揃っている。既定で装飾的なアニメーションを持たない。

### B. Qt Quick / QML

宣言的 UI。シーングラフを GPU で描画する。モバイル・タッチ向けの表現力が高い。

### C. ネイティブ API を OS ごとに実装（Cocoa / Win32）

最もネイティブだが、2 OS 分の UI を別々に書くことになる。

## 決定

**Qt Widgets を採用する。Qt Quick / QML は使用しない。**

理由。

1. **アニメーションが既定で無い。** UI 非機能要件（アニメーション禁止）と既定値が一致する。
   Qt Quick は逆に、既定の振る舞いやサンプルがトランジション前提で、要件を満たすために
   打ち消す作業が発生し続ける。
2. **GPU・コンポジタ負荷が低い。** シーングラフを持たないため、常時描画の必要がない。
   変換処理に CPU を使うアプリで、UI 側が資源を取り合わない。
3. **ネイティブのアクセシビリティ API に素直に乗る。** Qt Widgets は各 OS の
   アクセシビリティブリッジに標準で接続される。全機能をキーボードのみで操作可能にする要件
   （`docs/spec-core.md` §7）を、独自実装なしで満たしやすい。
4. **UI 形状が既製部品に適合する。** ファイル一覧は `QTableView` + モデル、
   設定パネルは `QFormLayout` でそのまま表現できる。QML では同等物を自作することになる。

## 帰結

- `src/app` の依存は `Qt6::Widgets` に限定する。`src/core` は `Qt6::Core` / `Qt6::Gui` のみ。
- QML エンジン（`Qt6::Qml` / `Qt6::Quick`）をリンクしない。混入は禁止（`docs/cpp-conventions.md` §1）。
- ジョブ一覧は `QAbstractTableModel` の派生（`JobTableModel`）で実装する（Phase 2）。
- ワーカースレッドから `QWidget` に触れない。UI 更新はキュー接続シグナル経由に限る
  （`docs/spec-core.md` §6）。
- 配布時は `macdeployqt` / `windeployqt` を使う（Phase 4）。QML 用の配置処理は不要になる。
