# ADR-0014: EXIF 全体の保持（`PreserveAll`）は Phase 3 では導入しない

- 状態: 承認（2026-08-09。Phase 3 の計画で D6 として提示し、承認を得た）
- 日付: 2026-08-09

---

## 背景

**ADR-0003** は `MetadataPolicy::PreserveAll` を `PreserveSupported` に改名し、
次のように決めていた。

> **EXIF 全体の保持は Phase 3 に送る。** 追加コーデックのライセンス調査と同じ
> タイミングで、外部ライブラリの導入可否を判断する。導入するなら
> `docs/licenses.md` の更新が先。

**ここがその判断の場である。**

前提として、Qt 6.8 には EXIF 全体（カメラ機種・GPS・撮影日時・レンズ情報等）を
読み書きする API が存在しない（ADR-0003 で公式ドキュメントを確認済み）。
実装するなら外部ライブラリが要る。

### 候補のライセンス（2026-08-09 に一次情報で確認）

| 候補 | ライセンス | 出典 | GPLv3 との両立 |
|---|---|---|---|
| exiv2 | **GPL-2.0-or-later**（`src/image.cpp` 冒頭の `SPDX-License-Identifier`） | `raw.githubusercontent.com/Exiv2/exiv2/main/src/image.cpp` | **可** |
| libexif | **LGPL-2.1**（`COPYING`） | `raw.githubusercontent.com/libexif/libexif/master/COPYING` | **可** |

**ライセンスは障害にならない。** どちらも本体の GPLv3-or-later と両立する。
したがって判断は技術と範囲の問題である。

## 選択肢

### A. Phase 3 で導入し、`MetadataPolicy::PreserveAll` を追加する

ADR-0003 が想定した形。字義どおりの「全部保持」が実現する。

### B. Phase 3 では導入せず、見送りを決定として記録する

`MetadataPolicy` は `PreserveSupported` / `StripAll` の 2 値のまま。

### C. 仕様から落とす（将来も `PreserveAll` を作らない）

`docs/spec-core.md` から関連記述を削り、EXIF 全体の保持を非スコープにする。

## 決定

**B を採る。Phase 3 では導入しない。将来の Phase での実装余地は残す。**

理由は 4 つある。

1. **「オプショナル依存」の枠に収まらない。**
   追加コーデックは `QImageIOPlugin` として**実行時に読み込まれ、アプリはリンクしない**
   （ADR-0013）。だから「無い環境でもビルド・起動する」が構造として成り立つ。
   EXIF ライブラリは `src/core` または `src/io` が**リンクする**必要があり、
   同じ枠組みに乗らない。無い環境でも動かすにはコード側の条件分岐が要る。
   **これは Phase 3 の受け入れ基準 2 が想定している形ではない。**
2. **`noexcept` 方針（ADR-0002）との整合を検討する必要がある。**
   コア層の関数は `noexcept` を維持すると決めている。exiv2 は例外を投げる
   C++ ライブラリであり、境界の設計を新たに決めなければならない。
   **その判断を追加コーデックの作業と同じコミットに混ぜない。**
3. **Phase 3 の受け入れ基準 3 項目のいずれにも含まれない。**
   3 項目はすべて追加コーデックに関するものである。
4. **扱う形式が増えた直後である。** ADR-0013 により AVIF / JPEG XL / PSD / RAW が
   加わった。EXIF の往復可否は形式ごとに異なるため、いま実装すると
   「形式ごとの差をどう仕様化するか」という別の設計課題が Phase 3 に流れ込む。

**C を採らないのは、要求そのものが消えたわけではないからである。**
`PreserveAll` は利用者にとって意味のある機能であり、実現手段も存在する。
「やらない」ではなく「今はやらない」を記録する。

## 帰結

- `MetadataPolicy` は **`PreserveSupported` / `StripAll` のまま**。コードは変更しない
- ADR-0003 の「Phase 3 で EXIF ライブラリを導入した場合、`PreserveAll` を
  **別の列挙値として追加**する。`PreserveSupported` の意味は変えない」という帰結は
  **有効なまま将来の Phase へ持ち越す**
- 実装する際に満たすべき条件を、判断が散らばらないようここに残す
  1. `docs/licenses.md` の更新が先（`CLAUDE.md` 停止条件 7）
  2. ADR-0002 の `noexcept` 方針との整合を先に決める（例外を投げるライブラリを
     コア層の境界でどう扱うか）
  3. ライブラリが無い環境でのビルド・起動を、どう担保するかを決める
  4. 形式ごとの EXIF 往復可否を、能力表と同じく**実測**で扱うか、
     仕様として固定するかを決める
- **利用者に見える挙動は Phase 2 から変わらない。** `PreserveSupported` は
  引き続き「向き」と「テキスト key/value」を保持する（ADR-0003 の訂正節）
