# ADR-0011: `cppcoreguidelines-owning-memory` は Qt の親子オーナーシップと両立しないため除外する

- 状態: 承認
- 日付: 2026-08-09

---

## 背景

`docs/cpp-conventions.md` §1 は、`new` / `delete` の直書きを禁じたうえで**例外を 1 つ明示している。**

> `new` / `delete` の直書き（**Qt の親付き `new` は `app/` 層のみ許可**）

Qt Widgets ではこれが標準の書き方であり、寿命は親ウィジェットが持つ。

```cpp
auto* central = new QWidget(this);          // 寿命は this（QMainWindow）が持つ
auto* column  = new QVBoxLayout(central);   // 寿命は central が持つ
```

一方 clang-tidy の `cppcoreguidelines-owning-memory` は、
**`new` の結果を「非所有」のポインタへ入れること自体を咎める。**
`gsl::owner<T*>` を使うか、スマートポインタで持つことを求める検査である。

**この 2 つは原理的に両立しない。** Qt の親子オーナーシップは
「生ポインタで受け取り、寿命は別のオブジェクトが持つ」という形そのものだからである。

### 実際に起きたこと

| Phase 2 のタスク | 件数 | 内容 |
|---|---|---|
| T8（`SettingsPanel`） | 1 件 | `QFormLayout` の生成 |
| T9（`MainWindow`） | **6 件** | 縦 3 段のレイアウトを組む使い捨ての `QWidget` / `QVBoxLayout` / `QHBoxLayout` |

T8 では回避策を 2 通り試し、いずれも指摘された。

| 書き方 | 結果 |
|---|---|
| `auto* layout = new QFormLayout(this);` | **指摘される**（局所変数） |
| `setLayout(new QFormLayout);` | **指摘される**（引数） |
| メンバ初期化子で持つ | 指摘されない |

T8 は 1 件だったためメンバ化で通したが、**T9 では使い捨ての入れ物 6 個が対象**になった。

## 選択肢

### A. `.clang-tidy` から `cppcoreguidelines-owning-memory` を除外する

指示書が明示的に許した書き方と両立しない検査を外す。

### B. すべてをメンバに昇格させる

構築後に一度も読まない入れ物 6 個がクラスに残る。
**リンタを通すためだけにクラス構造を歪めることになる。**

### C. 生成をヘルパー関数に隠す

どこかで `new` を変数か引数へ渡すため、指摘は消えない（T8 で 2 通り試して両方指摘された）。

## 決定

**A を採る。`.clang-tidy` から `cppcoreguidelines-owning-memory` を除外する。**

理由。

1. **`docs/cpp-conventions.md` §1 が明示的に許した形を、この検査は全面的に禁じる。**
   ADR-0002（コアの `noexcept` 方針）と `bugprone-exception-escape` の関係と同じ構図であり、
   Phase 1 でも同じ判断（検査側を外す）をしている。
2. **B は歪みが大きい。** 1 個ならまだしも、使い捨ての入れ物 6 個をメンバにすると
   「構築後に読まないメンバ」がクラスの見かけを支配する。
   **リンタのために設計を曲げない**という Phase 1 からの方針に反する。
3. **C は解決にならない。** 実測で確認済み。

## 帰結

- **`docs/phases.md` §3 に追記した。** 「除外可」と明示された枠の外にある 2 つ目の除外であり、
  1 つ目（`bugprone-exception-escape`）と同じ扱いで根拠を残す。
  `.clang-tidy` にも理由をコメントとして書いた。
- **除外はプロジェクト全体に効く。** `.clang-tidy` は 1 ファイルであり、層ごとに分けていない。
  ただし `core` / `io` では**親付き `new` そのものが規約で禁じられている**（同 §1）ため、
  実際に書かれるのは `app` 層だけである。
- **`core` / `io` に `new` が書かれていないことの機械検査は無い。** 現状は規約と
  コードレビューで守る。これが破られる事故が起きたら、不変条件スキャナ（INV8）として
  機械化することを提案する。**先回りしては作らない**（使う場面が無いうちに検査を増やさない）。
- T8 で `SettingsPanel` のレイアウトをメンバにした判断は**そのまま残す。**
  他のウィジェットもすべてメンバ初期化子で作っており、レイアウトだけ局所にする理由が無い。
  ただし**メンバにした理由はリンタではなくなった。**コメントを実態に合わせて書き直した。
- **これ以上の除外を増やすときも、同じように根拠を ADR に書き、`docs/phases.md` §3 へ追記する。
  黙って増やさない。**
